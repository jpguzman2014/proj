# Gaming Guess

A gaming guessing, trivia and party platform. Games, characters, weapons, items,
enemies, bosses, vehicles and locations — one database, many ways to play.

No login. No daily limit on practice. Installable as a PWA. Party multiplayer by
QR code, so friends join from their own phones with nothing to install.

## Run it

```bash
npm install
npm run dev          # the app on http://localhost:5173
npm run server       # the party room server on ws://localhost:8787
npm test             # engine, data integrity, filters and scoring
npm run build        # static site in dist/
```

The single-player game needs no server at all: `dist/` is a static bundle that
works on any free static host. The room server is only needed for party mode.
Point the client at a deployed one with `VITE_ROOM_SERVER=wss://rooms.example`.

## How it is put together

```
src/data/          the entity graph — games plus everything they connect to
src/engine/        question generation, clue ladder, filters, scoring
src/media/         media providers; the default one draws its own clue art
src/modes/         every game mode, as configuration
src/ui/            screens
src/net/           party room client
server/            party room server (WebSocket, in-memory)
tests/             engine, data and scoring tests
```

Four ideas hold the whole thing up.

**One entity graph.** A game connects to its characters, weapons, items,
enemies, bosses, vehicles and locations. Sub-entities inherit their game's
platforms, genres, era and tags, so a "PlayStation only" or "horror only" filter
works across every category without duplicating metadata. Adding a category
means adding a value to `EntityKind` and seeding rows.

**Question types are data.** `src/engine/questionTypes.ts` is a list of small
objects: a prompt, an answer, a distractor pool and which entity's art to show.
The same graph produces "which game is this", "who is this", "what year" and
"who developed it". Adding "guess the quote" is one entry plus rows.

**Modes are configuration.** `src/modes/registry.ts` holds timers, question
counts, lives, penalties and clue costs. The run screen, scoring, statistics and
party mode all read those rules, so Time Attack, Endless, Perfect Run and the
Daily Challenge share one code path.

**Media is separable from metadata.** See below.

## Fairness

The complaint about every competitor is that some questions are pure luck. Three
things push against that:

- **A clue ladder** on every question, ordered vague first and ending with
  something decisive. Opening clues costs points rather than being forbidden.
- **Near-miss distractors.** Wrong answers come from the same category and,
  where possible, the same era, so the shape of the options gives nothing away.
- **A leak guard in the engine.** Any clue containing the answer is dropped, and
  a question whose prompt contains its own answer is rejected outright. This is
  enforced for every question type, including ones added later, and is covered
  by a test.

After each question the player rates how hard it was. Ratings are stored locally
today and are the input a community difficulty score would use once there is a
backend to sync them to.

## Images and licensing

Game screenshots, cover art and character renders belong to their publishers,
and finding one online does not make it redistributable. **This app ships none
of them.**

Media sits behind `MediaProvider` in `src/media/provider.ts`, separate from the
metadata. The default provider draws each clue image from the entry's own data:
palette, kind and subtype drive a small SVG shape vocabulary, and the reveal
level controls crop and blur. Those bytes are generated by this repository. The
app icons are generated too, by `scripts/make-icons.mjs`.

Adding a licensed source later means registering another provider. The interface
already carries per-asset `credit` and `license`, and the UI already renders
them, so credit cannot be forgotten by accident.

## Party mode

The host opens the app on a laptop or TV, creates a room and gets a five
character code and a QR code. Friends scan it and are in — no app, no account.
Phones show the answers, the host screen shows the question.

The host's browser builds the questions and hands them to the server. The server
keeps the correct answer to itself, times each round and does the scoring, so a
player cannot read the answer out of their own client. Rooms live in memory and
are discarded when the host leaves or the room goes quiet. Nothing is persisted.

## Privacy and user-generated content

There is no account, no analytics, no advertising and no third-party request.
Scores, filters, ratings and reports live in `localStorage` on the device, and
the statistics page has a button that deletes all of it.

There is deliberately no user-generated content. Party display names are picked
from a fixed vocabulary in `shared/nicknames.json`, never typed, and the server
replaces anything outside it. That keeps the product outside user-to-user online
safety regimes such as the UK Online Safety Act. Adding typed names, chat or
reactions puts it back in scope, so treat any such request as a compliance
decision rather than a product one. See `LICENSING.md`.
